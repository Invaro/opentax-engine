# Corpus v0.53.0

## API changes

Packages in this release: core 1.0.0, solve 1.0.0, corpus-us-federal 0.53.0, compose 0.9.0. What each tier promises is in [docs/LIBRARY-API.md](https://github.com/Invaro/opentax-engine/blob/main/docs/LIBRARY-API.md).

- **`extendCorpus` (corpus, stable): an override needs a pin for every version it replaces.** If your rule overrides one of ours that has several versions (one per tax year), `pins` must hold each version that applies during your rule's dates. The error names the missing ones. Add them from `getCorpus().ruleHashes`, or set your rule's `effectiveTo` where your review ends. Before, one pin was enough and the other versions were replaced unreviewed.
- **`loadCorpus` / `extendCorpus` (stable): a malformed formula is refused at load.** An unknown expression kind, a money literal with a decimal point, a rate with a zero denominator or a non-positive `stepUnits` unit is now `CORPUS_INVALID`, with every problem listed. These used to surface as a `TypeError` or `RangeError` in the middle of an evaluation.
- **`evaluate` (core, stable): a fact that isn't a typed value is `FACT_INVALID`** (was a `TypeError`), and `FactValidationError` now has `factId`, also in `data()`.
- **New stable exports:** `compareIds` and `selectVersion` (core), `projectionFromVersion` (corpus).
- **`findCliffs` (solve, stable) scans the whole range.** The last interval, when the range isn't a whole number of steps, was skipped. Results can now include cliffs it used to miss.
- **Proofs carry engine version 1.0.0.** The format is unchanged (`schemaVersion` 2). A proof made by an earlier core verifies with this one, and the reverse.
- **Dependencies:** corpus and solve now accept any core 1.x (`^1.0.0`).

## What's new

- **A stable library API.** The four packages have a documented API, a tier for every export and a written compatibility policy: [docs/LIBRARY-API.md](https://github.com/Invaro/opentax-engine/blob/main/docs/LIBRARY-API.md), with six runnable examples. core and solve follow semantic versioning from 1.0.0; the corpus version stays the release number; compose is provisional.
- **What we promise about ids:** fact ids, enum values, accepted ranges, defaults, rule ids and extension points are not removed, narrowed or repurposed, and a published rule version never changes. A change is a new version with a number never used before.
- **Fixed in the engine:**
  - A proof object edited in memory after it was hashed could still verify, because the hashing code remembered an object's canonical form for the life of the process. A stored or re-parsed proof was always checked correctly. The memory now lasts one call.
  - The Merkle root depended on the machine's language: ids were sorted with the runtime's locale, so Czech, Lithuanian, Turkish and about a dozen other settings computed a different root and rejected valid proofs. Ids now sort in one fixed order (`compareIds`; [docs/PROOF-FORMAT.md](https://github.com/Invaro/opentax-engine/blob/main/docs/PROOF-FORMAT.md) § 4). It is the order English locales already gave, so every published root is unchanged.
  - State composer amounts were formatted in the machine's language; they are always `$1,234,567` now.
- **Each tarball has a README.**

Every answer, every proof tree and the Merkle root are identical to v0.52.0: no rule or fact changed. A differential on every fixture (1,905), the IRS ATS TY2025 scenarios, the AMT regression cases and every rule found no difference, and 21,000 random evaluations computed identically. The contract is enforced in CI on Node 20, 22 and 24: a committed API report, a baseline of this release's ids and declarations, a frozen corpus whose proofs were made by core 0.1.0, and a job that installs the tarballs into an empty project.
